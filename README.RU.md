# docs-techwriter

Скилл для ИИ-ассистентов (Claude Code, Opencode, Codex): пишет и проверяет
техническую документацию на английском и русском — README, руководства, справку
CLI, заметки к выпуску, журналы изменений. Три вида работы: английский документ
сам по себе, русская версия английского и русский документ без английского
оригинала.

Главное правило для русского: **хорошая русская версия — не перевод.** Это то
же содержание, изложенное так, как изложил бы его русский технический писатель.
Если фраза не переводится, скилл перестаёт переводить и описывает, что
происходит на деле.

Для английского текста читатель по умолчанию — не носитель языка: одна мысль в
предложении, действующее лицо названо, никаких идиом, которые надо
расшифровывать.

Каждое правило взято из одного из трёх источников, и источник назван рядом:

- дефект, который читатель нашёл в настоящем документе;
- измеренное исследование того, как профессиональные редакторы правят машинный
  текст (LAMP, CHI 2025; Shaib et al., 2025);
- опубликованное руководство по стилю: Google developer documentation,
  Microsoft Writing Style Guide, Microsoft Russian Style Guide.

Рядом с каждым правилом из руководства записано, сколько раз оно сработало на
настоящих README. Если ни разу, так и сказано: «живого случая пока нет». Для
ассистента это значит: такое правило — повод присмотреться к фразе, но не
основание её переписывать.

## Что делает прогон

Для русской версии:

1. Читает 2–3 русских документа того же проекта и берёт из них тон.
2. Пишет русский текст по смыслу английского, а не по его предложениям. Потом
   закрывает английский текст и проверяет, что каждый абзац говорит читателю
   сделать то же самое.
3. Ищет известные кальки и канцелярит — `references/lexicon.md`.
4. Проверяет четырнадцать конструкций, которые ломаются в русском, —
   `references/patterns.md`.
5. Прогоняет пятнадцать механических проверок — `references/checks.md`:
   разошедшиеся между версиями факты, ссылки и якоря, настоящие пути в
   примерах, длину предложений, HTML-сущности, типографику.

Шаги 3–5 идут по одному. Проход «всё сразу» замечает один-два самых заметных
дефекта и пропускает остальные.

Для английского документа порядок тот же, только без перевода: прочитать
соседние документы, проверить смысл каждого абзаца, затем английские правила из
`references/en-side.md` и общие механические проверки — по одной за проход.

## Что нужно для работы

| Что | Для чего | Обязательно |
|---|---|---|
| ассистент: Claude Code, Opencode или Codex | сам скилл | да |
| `python3` | установка правила; проверки 1, 3, 5, 6, 9, 12, 13, 15 | да |
| `rg` (ripgrep), `awk` | поиск в проверках 2, 4, 7, 14 и в словаре | да |
| `typograf-cli` 6.2.1 | проверка 15: кавычки, тире, пробелы | нет: скилл работает и без него, но кавычки, тире и пробелы никто не проверит |
| Node.js 18.19+ или 20.6+ с `npm` | только чтобы поставить и запустить `typograf-cli`; больше скиллу Node нигде не нужен | только вместе с `typograf-cli` |

`typograf-cli` — единственная внешняя программа. `install.sh` предлагает её
поставить, если запущен в терминале, и ставит в
`~/.local/share/docs-techwriter/typograf` со ссылкой `~/.local/bin/typograf` —
через `npm --prefix`, без `sudo`. Если нет Node.js, установщик печатает команду
системного менеджера пакетов и предлагает её выполнить: `apt-get` (Debian,
Ubuntu), `dnf` или `yum` (RHEL, Fedora, CentOS), `brew` (macOS). В Linux этой
команде нужен `sudo`, и выполняется она только после ответа «да» в терминале.

Минимальная версия Node измерена, а не взята из пакета. `typograf-cli` 6.2.1
заявляет Node 14, но вызывает `import.meta.resolve()`, которого нет в 18.18 и
20.5. RHEL 8/9 и их клоны по умолчанию ставят Node 16, поэтому там установщик
берёт поток модуля `nodejs:20`. В Ubuntu 22.04 пакет `nodejs` версии 12 — это
слишком старая версия; установщик так и пишет и отсылает к nodejs.org,
NodeSource или nvm.

Проверено в контейнерах: Debian 13, Fedora 44 и AlmaLinux 9 — полный путь от
отсутствия Node до зелёных тестов. На настоящем Маке установщик не запускали,
только в симуляции — см. [macOS: ожидаемый сценарий](#macos-ожидаемый-сценарий).

Рассчитано на Linux (Debian/Ubuntu и семейство RHEL) и macOS; для macOS в
установщике есть своя ветка, прогнанная только в симуляции. Windows не
планировалась и не проверялась даже так. Установщик написан на bash: в Git Bash или
Cygwin он пропустит `typograf`, а остальное там никто не запускал. Сам скилл —
это Markdown и один скрипт на Python, поэтому в Windows его можно попробовать,
скопировав `skills/docs-techwriter/` в каталог скиллов ассистента вручную.
Правило-триггер тогда тоже придётся подключить вручную.

### macOS: ожидаемый сценарий

На настоящем Маке установщик никто не запускал. Этот сценарий прочитан из кода
`install.sh`, а часть шагов прогнана на Linux в симуляции. Симуляция — это
образ `bash:3.2`, подставной `uname`, который отвечает `Darwin`, и подставной
`brew`, который только записывает свои аргументы.

Почему 3.2: это до сих пор системный `/bin/bash` в актуальной macOS — `3.2.57`
на macOS Tahoe 26.4.1 в мае 2026 года (github.com/nitefood/asn/issues/108).
Apple держится за него, потому что следующие версии bash выходят под GPLv3, и
вместо обновления сделала оболочкой по умолчанию zsh. Установщик начинается с
`#!/usr/bin/env bash`, поэтому, если в `PATH` раньше стоит bash 5 из Homebrew,
запустится он; этот случай и проверен на Linux.

1. Скилл копируется в каждый найденный каталог ассистента. В симуляции —
   работает.
2. Правило-триггер подключается через `python3`. Если `python3` нет,
   установщик так и пишет и правило не ставит; тогда скилл загружается, только
   когда его зовут по имени.
3. Если нужен `typograf-cli`, а Node.js нет, установщик при наличии Homebrew
   предлагает `brew install node` и запускает его только после «да» в
   терминале. Без Homebrew он отсылает на nodejs.org. Обе ветки прогнаны в
   симуляции, настоящий `brew` — нет.
4. `typograf-cli` ставится в `~/.local/share/docs-techwriter/typograf`, ссылка —
   `~/.local/bin/typograf`. Этого каталога нет в стандартном `PATH` macOS;
   установщик предупредит, а проверка 15 найдёт программу там и так.

## Установка

```bash
git clone <этот репозиторий> && cd docs-techwriter
./install.sh --dry-run    # что будет записано
./install.sh
```

`install.sh` копирует скилл во все найденные ассистенты (`~/.claude/skills`,
`~/.config/opencode/skills`, `~/.codex/skills`) и ставит рядом правило-триггер
`rules/docs-techwriter-trigger.md`. Без правила скилл не срабатывает: когда русский
текст пишут вместе с английским, это выглядит как обычная работа и под описание
скилла не попадает. Opencode и Codex читают правило, только если на него
ссылается их конфиг, поэтому установщик дописывает запись в `instructions[]`
файла `opencode.json` и `@`-ссылку в `~/.codex/AGENTS.md`. Файл, который он
меняет, сначала копируется в резерв.

`--no-rule` ставит только скилл. `--skills-dir D` ставит скилл в каталог `D` и
никакие конфиги не трогает. `--with-typograf` ставит `typograf-cli` без вопроса,
`--no-typograf` не предлагает его вовсе. Без терминала и без этих ключей
`typograf` пропускается.

## Что где лежит

```
skills/docs-techwriter/SKILL.md     порядок работы и ограничители
skills/docs-techwriter/references/  lexicon, patterns, checks, en-side
skills/docs-techwriter/scripts/     typograf_check.py — проверка 15
rules/docs-techwriter-trigger.md    правило, которое загружает скилл
lib/wire.py                         ставит правило в один ассистент
install.sh, release.sh              установка; проверки выпуска
tests/                              тесты typograf_check.py
```

## Выпуск

Поднять `version:` в `SKILL.md`, добавить раздел в `CHANGELOG.md`, закоммитить,
затем:

```bash
./release.sh check    # версия, журнал, тег, HEAD и все установленные копии совпадают
./release.sh tag
```

## Как присылать правки

Новое правило приходит вместе с документом, который оно сломало: фраза, что в
ней не так, чем её заменили. Правило, выведенное по аналогии с английским, не
принимается.

Сообщения коммитов пишутся по-английски, вместе с телом. Цитата русского текста
в сообщении остаётся цитатой: там русский и есть предмет правки.
