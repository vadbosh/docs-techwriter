# ru-tech-docs

Скилл для ИИ-ассистентов (Claude Code, Opencode, Codex): пишет русскую версию
английской технической документации — README, руководства, справку CLI,
заметки к выпуску, файлы скиллов — и проверяет готовую русскую версию на кальки
и фразы, которых никто не произнёс бы вслух.

Главное правило: **хорошая русская версия — не перевод.** Это то же содержание,
изложенное так, как изложил бы его русский технический писатель. Если фраза не
переводится, скилл перестаёт переводить и описывает, что происходит на деле.

Каждое правило взято из одного из двух источников: дефект, который читатель
нашёл в настоящем документе, или измеренное исследование того, как
профессиональные редакторы правят машинный текст (LAMP, CHI 2025; Shaib et al.,
2025). Выдуманных правил нет.

## Что делает прогон

1. Читает 2–3 русских документа того же проекта и берёт из них тон.
2. Пишет русский текст по смыслу английского, а не по его предложениям. Потом
   закрывает английский текст и проверяет, что каждый абзац говорит читателю
   сделать то же самое.
3. Ищет известные кальки и канцелярит — `references/lexicon.md`.
4. Проверяет четырнадцать конструкций, которые ломаются в русском, —
   `references/patterns.md`.
5. Прогоняет пятнадцать механических проверок — `references/checks.md`:
   разошедшиеся между версиями факты, ссылки и якоря, настоящие пути в
   примерах, длину предложений, HTML-сущности, типографику.

Шаги 3–5 идут по одному. Проход «всё сразу» замечает один-два самых заметных
дефекта и пропускает остальные.

Для английского текста есть своя страница, `references/en-side.md`. Она
грузится, только когда пишут или правят английский текст.

## Что нужно для работы

| Что | Для чего | Обязательно |
|---|---|---|
| ассистент: Claude Code, Opencode или Codex | сам скилл | да |
| `python3` | установка правила; проверки 1, 3, 5, 6, 9, 12, 13, 15 | да |
| `rg` (ripgrep), `awk` | поиск в проверках 2, 4, 7, 14 и в словаре | да |
| Node.js 12.20 или новее с `npm`, затем `typograf-cli` 6.2.1 | проверка 15: кавычки, тире, пробелы | нет — без него проверка пропускается |

`typograf-cli` — единственная внешняя программа. `install.sh` предлагает её
поставить, если запущен в терминале, и ставит в
`~/.local/share/ru-tech-docs/typograf` со ссылкой `~/.local/bin/typograf` —
через `npm --prefix`, без `sudo`. Если нет Node.js, установщик печатает команду
системного менеджера пакетов и предлагает её выполнить: `apt-get` (Debian,
Ubuntu), `dnf` или `yum` (RHEL, Fedora, CentOS), `brew` (macOS). В Linux этой
команде нужен `sudo`, и выполняется она только после ответа «да» в терминале.

Поддерживаются Linux (Debian/Ubuntu и семейство RHEL) и macOS. **Windows не
поддерживается**: установщик написан на bash, а в MSYS и Cygwin он пропускает
`typograf`.

## Установка

```bash
git clone <этот репозиторий> && cd ru-tech-docs
./install.sh --dry-run    # что будет записано
./install.sh
```

`install.sh` копирует скилл во все найденные ассистенты (`~/.claude/skills`,
`~/.config/opencode/skills`, `~/.codex/skills`) и ставит рядом правило-триггер
`rules/ru-tech-docs-trigger.md`. Без правила скилл не срабатывает: когда русский
текст пишут вместе с английским, это выглядит как обычная работа и под описание
скилла не попадает. Opencode и Codex читают правило, только если на него
ссылается их конфиг, поэтому установщик дописывает запись в `instructions[]`
файла `opencode.json` и `@`-ссылку в `~/.codex/AGENTS.md`. Файл, который он
меняет, сначала копируется в резерв.

`--no-rule` ставит только скилл. `--skills-dir D` ставит скилл в каталог `D` и
никакие конфиги не трогает. `--with-typograf` ставит `typograf-cli` без вопроса,
`--no-typograf` не предлагает его вовсе. Без терминала и без этих ключей
`typograf` пропускается.

## Что где лежит

```
skills/ru-tech-docs/SKILL.md        порядок работы и ограничители
skills/ru-tech-docs/references/     lexicon, patterns, checks, en-side
skills/ru-tech-docs/scripts/        typograf_check.py — проверка 15
rules/ru-tech-docs-trigger.md       правило, которое загружает скилл
lib/wire.py                         ставит правило в один ассистент
install.sh, release.sh              установка; проверки выпуска
tests/                              тесты typograf_check.py
```

## Выпуск

Поднять `version:` в `SKILL.md`, добавить раздел в `CHANGELOG.md`, закоммитить,
затем:

```bash
./release.sh check    # версия, журнал, тег, HEAD и все установленные копии совпадают
./release.sh tag
```

## Как присылать правки

Новое правило приходит вместе с документом, который оно сломало: фраза, что в
ней не так, чем её заменили. Правило, выведенное по аналогии с английским, не
принимается.

Сообщения коммитов пишутся по-английски, вместе с телом. Цитата русского текста
в сообщении остаётся цитатой: там русский и есть предмет правки.
