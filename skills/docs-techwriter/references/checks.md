# The mechanical pass

Re-reading finds wording. It does not find that the two versions now describe
different software. Run these; checks 1–14 each caught a real defect, 15 comes
from a style guide.

## 1. Факты разошлись между версиями

Самое дорогое и самое незаметное. Проверяй перечисляемое: команды, числа, имена
файлов, пороги.

Список файлов не пишется руками: пары берутся из того, что лежит на диске —
`X.md` ↔ `X.RU.md`, `X.md` ↔ `X.ru.md` и `X.en.md` ↔ `X.ru.md`. Заполняешь только `checks`: числа,
команды и имена, которые обязаны стоять в обеих версиях **твоего** документа.

```bash
python3 - <<'PY'
import re, glob, pathlib
checks = {                      # своё на каждый документ
    "порог 400":   r"\b400\b",
    "версия 3.10": r"3\.10",
}
pairs = []
for en in glob.glob("*.md") + glob.glob("docs/*.md"):
    for ru in (en[:-3] + ".RU.md", en[:-3] + ".ru.md", en.replace(".en.md", ".ru.md")):
        if ru != en and pathlib.Path(ru).exists():
            pairs.append((en, ru)); break
for en, ru in pairs:
    files = {f: pathlib.Path(f).read_text(encoding="utf-8") for f in (en, ru)}
    print(f"{'':18}" + "".join(f"{f.split('/')[-1][:12]:>14}" for f in files))
    for name, pat in checks.items():
        print(f"  {name:16}" + "".join(f"{len(re.findall(pat, s)):>14}" for s in files.values()))
PY
```

Ноль в одной колонке при единице в остальных — расхождение. Так нашлось, что
русский мануал описывал две команды там, где инструмент выполняет три.

Факт расходится и внутри одного файла: в разделе о секретах README стояло
«девятнадцать шаблонов», а через двадцать строк — «примерно 150 правил вместо
десяти». Таблица выше этого не видит: она сравнивает версии, а не абзацы. Для
чисел, повторённых в одном документе, впиши в `checks` все написания — и цифрой,
и словом.

## 2. Примеры совпадают дословно

Имена файлов и даты в примерах должны быть одинаковыми во всех версиях — иначе
читатель, перешедший из README в мануал, встречает другой файл.

Шаблон под свои примеры: здесь ищутся имена вида `NN-slug.md`, у другого проекта
это будут имена команд, ключи задач, хосты — что стоит в примерах.

```bash
rg -n "0[0-9]-[a-z-]*\.md" -g '*.md' . | rg -o "[0-9]{2}-[a-z0-9-]+\.md" | sort | uniq -c
```

Так нашлось `01-pipeline.md` против `02-pipeline.md` и дата `2026-09-01` в
примере front matter против `2026-08-05` в таблице **того же файла**.

## 3. Ссылки и якоря

```bash
python3 - <<'PY'
import re, os, glob, pathlib
bad = 0
for f in glob.glob("*.md") + glob.glob("docs/*.md"):
    s = pathlib.Path(f).read_text(encoding="utf-8")
    s = re.sub(r'(?ms)^ {0,3}(`{3,}|~{3,}).*?^ {0,3}\1', '', s)   # примеры в блоках кода
    for l in re.findall(r'\]\((?!\w+:)([^)#\s]+)(?:#[^)\s]*)?(?:\s+"[^"]*")?\)', s):
        if not os.path.exists(os.path.normpath(os.path.join(os.path.dirname(f), l))):
            print("  ✗ файл", f, "→", l); bad += 1
    heads = {re.sub(r'[^a-zа-яё0-9 _-]', '', h.lower()).replace(' ', '-')
             for h in re.findall(r'^#{2,4} (.+)', s, re.M)}
    for a in set(re.findall(r'\]\(#([^)]+)\)', s)) - heads:
        print("  ✗ якорь", f, "→ #" + a); bad += 1
print("битых:", bad)
PY
```

Кириллические якоря работают: `#установка` для `## Установка`. Регистр и пробелы
приводятся так же, как в латинице.

Три вещи в этом блоке — не украшение, каждая закрывает ложное срабатывание:
заголовки берутся с `##` по `####`, иначе ссылка на `###` объявляется битой;
`ё` и `_` остаются в наборе символов, иначе `#ёлка` считается битым, а
несуществующий `#лка` — целым; `(?!\w+:)` пропускает любую схему, а не только
`http`, иначе `mailto:` и `tel:` ищутся на диске как файлы. Блоки кода
вырезаются до поиска: ссылка-пример `[x](path/to/your-file.md)` не обязана
существовать. Путь берётся до первого пробела: `[x](file.md "Заголовок")` —
ссылка с подсказкой, а не файл с пробелом в имени.

## 4. Ширина строк и диаграммы

```bash
rg --files -g '*.md' | xargs -r awk 'length>88 && $0 !~ /^\|/ && $0 !~ /^\[/ {print FILENAME":"FNR" ("length")"}'
```

`FNR`, не `NR` — иначе номера строк врут при нескольких файлах. Список файлов
даёт `rg --files`, а не `*.md docs/*.md`: без каталога `docs/` `awk` падает на
несуществующем имени с кодом 2. `length` считает символы только в UTF-8-локали;
под `LC_ALL=C` русская строка вдвое длиннее, и порог срабатывает на каждой.

Таблицы и строки со ссылками длинными остаются, их не перенести. Диаграмму из
рамок проверяй **по индексу символа**, а не глазами:

```bash
python3 -c "
import glob, pathlib
for f in glob.glob('*.md') + glob.glob('docs/*.md'):
    cols={l.index(c) for l in pathlib.Path(f).read_text(encoding='utf-8').split(chr(10))
          for c in '┐├┘' if c in l}
    if cols: print(f, cols, 'ok' if len(cols)==1 else 'СМЕЩЕНО')"
```

Так нашёлся соединитель, стоявший на колонку левее двух других.

## 5. Посторонние символы

Правка через скрипт или копирование из браузера заносят три рода символов:
чужую письменность, невидимые символы и латинскую букву внутри русского слова.

```bash
python3 -c "
import glob, pathlib
hidden = {0x00AD, 0x2060, 0xFEFF} | set(range(0x200B, 0x2010))
for f in glob.glob('*.md') + glob.glob('docs/*.md'):
    s = pathlib.Path(f).read_text(encoding='utf-8')
    bad = {c for c in s if 0x2E80 < ord(c) < 0xFFFF or ord(c) in hidden}
    print(f, sorted(hex(ord(c)) if ord(c) in hidden else c for c in bad) or 'чисто')"
rg -n '[а-яёА-ЯЁ][a-zA-Z]|[a-zA-Z][а-яёА-ЯЁ]' -g '*.md' .    # «сеpвер» с латинской p
```

Так нашлись иероглифы `判断`, попавшие в текст из-за опечатки в замене, и
`0xfe0f` в строке `>️` — от значка «⚠️» в цитате удалили сам знак, а невидимый
селектор варианта остался. Невидимые символы печатаются кодом: `0x200b` — пробел нулевой ширины, `0xad` —
мягкий перенос; на экране их нет, а поиск по слову с ними не находит слово.
Смешанное слово выглядит русским и не находится поиском по-русски; совпадение в
обратных кавычках или в имени вида `IPv6адрес` смотри глазами.

## 6. Разделители и пустые строки

После перестановки разделов остаются задвоенные `---` и тройные переводы строк.
Хуже них — `---` сразу под строкой текста, без пустой строки: Markdown читает
такую пару как заголовок, и весь абзац над чертой становится крупным `<h2>`.

```bash
python3 -c "
import re, glob, pathlib
for f in glob.glob('*.md') + glob.glob('docs/*.md'):
    s = pathlib.Path(f).read_text(encoding='utf-8')
    print(f, 'задвоенных ---:', len(re.findall(r'\n---\n\n---\n',s)),
             'тройных пустых:', s.count(chr(10)*3))
    lines, fence = s.split(chr(10)), False
    for i, l in enumerate(lines):
        if re.match(r'^ {0,3}(\`\`\`|~~~)', l): fence = not fence
        if not fence and i and re.fullmatch(r'-{3,}|={3,}', l.strip()) \
           and lines[i-1].strip() and not lines[i-1].lstrip().startswith('|'):
            print(f'{f}:{i+1}: черта под текстом — абзац выше станет заголовком')"
```

Так нашёлся README, где абзац «Имеет смысл, только если заметки лежат внутри
git-репозитория…» стоял прямо над `---` и отрисовывался заголовком: `pandoc -f
commonmark` выдал `<h2>`. На экране редактора это обычный текст с чертой под
ним, поэтому глазами не ловится.

## 7. Настоящие пути в примерах

Самая повторяемая ошибка из всех перечисленных: три раза за два дня. Пример
делается вставкой **настоящего вывода команды** — так он честнее выдуманного, —
и вместе с выводом в документ уезжают внутренние имена: каталоги проектов, хосты,
пути к чужим конфигам. В публичном репозитории это уже не пример, а утечка.

```bash
rg -n "/(home|srv|opt|mnt|root|Users)/[A-Za-z0-9_.-]+|[A-Za-z]:\\\\Users\\\\|[0-9]{1,3}(\.[0-9]{1,3}){3}" -g '*.md' . \
  | rg -v "/home/user|/Users/user|example\."
```

Первый шаблон знает и домашний каталог `root` (`/root/…`), и macOS
(`/Users/…`), и Windows (`C:\Users\…`): утечка пути администратора — самая
частая, потому что примеры снимают с той же машины. Второй фильтр — список
условных имён, принятых в этом документе; пополняй его своими. Совпадение не значит «ошибка», оно значит «посмотри»: `/srv/infra/app` в
примере вымышлен и законен, а путь рабочего каталога с именем заказчика — нет,
хотя выглядят они одинаково. Различает только знание, чей это путь.

Вывод при этом сохраняй настоящий: подменять надо **пути**, а не поведение.
Если после подмены обещание «здесь настоящий вывод» становится полуправдой,
оговори это одной строкой — «пути условные, вывод настоящий».

Проверять надо и английскую версию: утечка не про язык, а про копипасту, и в
английский файл она попадает тем же движением.

## 8. Потери при перестановке

## 9. Длина предложения — счётом, а не на слух

Предложение длиннее тридцати слов в русском тексте почти всегда список,
соединённый точками с запятой. Читатель доходит до конца и не помнит начала.

```bash
python3 -c "
import re, sys, pathlib
for f in sys.argv[1:]:
    if not pathlib.Path(f).is_file(): continue      # docs/*.ru.md без docs/
    s = pathlib.Path(f).read_text(encoding='utf-8')
    s = re.sub(r'\`\`\`.*?\`\`\`', '', s, flags=re.S)
    s = re.sub(r'(?m)^[|>#*-].*\$', '', s)
    for x in re.split(r'(?<=[.!?])\s+', s):
        n = len(x.split())
        if n > 30:
            print(f, n, 'слов:', ' '.join(x.split())[:70])
" README.RU.md docs/*.ru.md
```

Лечится двоеточием и списком, а не расстановкой запятых.

Выбрасываются не только таблицы: заголовок, пункт списка и цитата тоже уходят.
Иначе заголовок приклеивается к первому предложению абзаца, а список из четырёх
пунктов без точек считается одним предложением на полсотни слов — измерено на
живом мануале, где такая «находка» пережила два прохода, прежде чем кто-то
открыл строку. Порог для английского — 35 слов: при том же смысле английская
версия длиннее.

## 10. Правка дошла до обеих версий

Правка одной версии без второй — расхождение, которого проза не показывает.
После правки прежняя формулировка должна исчезнуть из обеих:

```bash
rg -n "прежняя формулировка" README.md README.RU.md
case $? in
  0) echo "ОСТАЛОСЬ" ;;
  1) echo "чисто" ;;
  *) echo "ПРОВЕРКА НЕ ОТРАБОТАЛА" ;;
esac
```

Ветвиться по коду возврата, а не по `&&`/`||`: у `rg` код `1` это «не нашлось»,
а `2` — «не смог прочитать». Через `||` они попадают в одну ветку, и опечатка в
имени файла печатает `чисто` — ответ, которым проверку и заканчивают.

Измерено: замена применилась только к русской версии — английская осталась на
прежнем выпуске. Заметил это не человек и не проверка репозитория, а `assert`
внутри скрипта правки. Скрипт, меняющий обе версии, обязан падать, когда
искомый текст не найден: значит текст разошёлся с тем, что скрипт ищет.

## 11. Правка текста идёт инструментом правки, а не через heredoc

Документ, который правят `cat <<EOF`, проходит через три слоя кавычек — шелл,
heredoc и сам текст. Внутри чинимого абзаца может оказаться свой блок кода со
своим `<<`, и тогда внешний heredoc закрывается на середине: часть текста
уезжает в шелл как команды.

Так сломался абзац этой самой страницы. Правило: одну правку в одном файле
делают редактором, скрипт — только когда одна и та же замена идёт по нескольким
файлам сразу.

## 12. Заголовок называет предмет

Заголовок читают из оглавления, где предыдущей строки нет. «Чего он не делает»
оттуда не значит ничего. Структура описана в `patterns.md`, здесь — команда:

```bash
python3 -c "
import re, pathlib
mest = r'\b(он|его|ему|им|она|они|это|этот|эта|эти|этим|этого|таком|такой)\b'
skip = {'.git', 'node_modules', '.memsearch', '.venv'}
for p in sorted(pathlib.Path('.').rglob('*.md')):
    if skip & set(p.parts) or p.name.startswith('review-'): continue
    for h in re.findall(r'(?m)^#+ .+\$', p.read_text(encoding='utf-8')):
        head = h.split('<!--')[0].split('←')[0]   # без пояснений справа
        if re.search(mest, head.lower()) or re.match(r'^#+ (What|How|Why) it\b', head):
            print(p, h.strip())"
```

Обходится **всё дерево**, а не корень и `docs/`: заголовок без предмета одинаково
мешает в `FAST-START.RU.md`, в заметках `kb/` и в страницах скила. Пропускаются
служебные каталоги и файлы `review-*.md` — обзор это наряд на одну правку, его
заголовки живут по своим правилам.

Совпадение не приговор: «Чего эта защита не делает» предмет называет. Приговор —
заголовок, из которого предмет не виден без соседнего раздела.

Два законных случая, которые всплывают сразу, как только обход стал полным:

- **скелет заметки.** `## Где это лежит`, `## Зачем этот каталог` — это шапки,
  которые инструмент заметок ставит сам, и предмет стоит в заголовке файла
  строкой выше. Переименовывать их поодиночке бессмысленно: шапка придёт снова
  с новой заметкой. Менять — так в шаблоне.
- **английское `## How it works` в файле скила.** Предмет назван в `name:`
  фронт-маттера, который читает не человек, а модель, и раздел там ровно один.

Мерь не число совпадений, а число файлов, которые читает человек: в README,
мануале и быстром старте заголовок без предмета — дефект всегда.

Переименовал заголовок — перепроверь якоря проверкой 3: ссылка `](#...)` на
прежний текст ломается молча.

## 13. Глоб в списке — действительно глоб

Список путей, расширений или имён внутри блока кода читается как машинный, хотя
его никто не проверял. Одна запись вида `*.x` рядом с настоящими глобами — и
читатель считает покрытым то, что не покрыто.

Проверять надо не текстом, а поведением: прогнать каждую запись через ту
программу, о которой список.

```bash
python3 -c "
import re, pathlib, sys
s = pathlib.Path(sys.argv[1]).read_text(encoding='utf-8')
blocks = re.findall(r'(?ms)^\`\`\`[a-z]*\n(.*?)^\`\`\`', s)
for tok in {t for b in blocks for t in b.split()
            if re.fullmatch(r'[~A-Za-z0-9_./*?-]*[*?][~A-Za-z0-9_./*?-]*', t) and re.search(r'[A-Za-z0-9.~/]', t)}:
    print(tok)" docs/patterns.ru.md | sort
```

Отбор по форме токена: только символы пути, хотя бы одна `*` или `?` в любом
месте — `*.env`, `/proc/*/environ`, `~/.aws/*`, `**/*.pem`. Кириллица и пробел
в токен не входят, поэтому `**жирный**` из соседней строки не попадает, а голые
`*` и `**` отсекает требование хотя бы одной буквы, цифры или знака пути.

Дальше по каждому токену — команда программы и её код возврата, а не чтение
исходника. Пример, на котором проверка и появилась:

```
cat server.pem   exit=2   запрещено
cat deploy.key   exit=2   запрещено
cat prod.env     exit=0   ПРОХОДИТ   ← а в списке стояло *.env
```

Три соседних записи выглядели одинаково, вели себя по-разному, и расходились в
сторону, опасную для читателя: он считал файл защищённым.

Заодно этим же прогоном ловится случай хуже: **две реализации отвечают
по-разному**. Там же выяснилось, что один потребитель списка раскрывает `*.env`
как настоящий глоб, а два других требуют границу слева. Документация не может
быть верной для обоих — значит, она обязана назвать расхождение.

## 14. HTML: сущность прячет символ от поиска

Страница на HTML пишет тире и неразрывный пробел как `&mdash;` и `&nbsp;`,
поэтому поиск по литералу их не видит: файл выглядит чистым, а читатель видит
символ. Проверять надо обе формы — и то же касается кавычек (`&laquo;`,
`&raquo;`) и стрелок (`&rarr;`).

```bash
rg -c "&(mdash|ndash|nbsp|laquo|raquo|rarr|hellip);" *.html
rg -n "—|«|»|→" *.html | head            # литералы: обе формы в одном файле — разнобой
```

Проверяется текст, который читатель видит, **и** текст, который он видит
изредка: `alt`, `title`, `aria-label`, `placeholder`, `<meta name="description">`,
`<title>`. Имена тегов, атрибутов, классов и `id` — код: не переводятся и не
проверяются.

```bash
rg -o '(alt|title|aria-label|placeholder)="[^"]*"' *.html | rg "[А-Яа-яЁё]"
```

Разнобой форм в одном документе — находка: один абзац правили редактором, другой
скриптом, и дальше они расходятся при каждой правке.

## 15. Типографика: кавычки, тире, пробелы

Прямые кавычки вместо «ёлочек», дефис вместо тире, двойной пробел — правка,
которую никто не читает глазами, потому что на экране всё похоже. Проверку
делает [typograf](https://github.com/typograf/typograf-cli) — внешняя программа
на Node.js, единственная в этом скилле. Ставит её `install.sh` из репозитория
скилла (`--with-typograf`) или `npm install -g typograf-cli`. Нет её — проверка
пропускается, остальные четырнадцать от неё не зависят.

Запускается не сам `typograf`, а обёртка из каталога скилла:

```bash
python3 <каталог скилла>/scripts/typograf_check.py README.RU.md docs/*.ru.md
python3 <каталог скилла>/scripts/typograf_check.py --lang en README.md docs/*.en.md
# 0 — править нечего, 1 — есть строки к правке, 2 — typograf не найден или упал
```

Для английского текста — `--lang en`: правила английские, а прямые кавычки не
считаются ошибкой — в английском Markdown они норма, и `typograf` к тому же
путал их в начале абзаца. Остаются тире вместо дефиса, двойные пробелы,
многоточие. На восьми английских README соседних проектов — ноль строк к
правке, на файле с дефисом вместо тире и двойным пробелом — находка.

Обёртка нужна по двум причинам, обе измерены на typograf-cli 6.2.1:

- `typograf` не знает Markdown. На сыром файле он превращает `echo "x" -- y` в
  блоке кода в `echo «x» — y`. Обёртка прячет блоки и строки кода, ссылки,
  маркеры списков и выделения, front matter и только потом отдаёт текст;
- `typograf --lint` показывает одно место на правило и выходит с кодом 0 даже
  при находках. Обёртка печатает каждую строку, которую `typograf` изменил бы:
  `файл:строка`, затем строка до и после.

Абзацы уходят в `typograf` по отдельности, массивом JSON: иначе одна непарная
кавычка в начале файла превращает все ёлочки ниже в лапки.

Выключены правила, которые на технической документации ошибаются:

- даты ISO — `2026-10-04` остаётся как есть;
- `ru/dash/to` и `ru/dash/kakto` — они гадают по смыслу, и «так что то, что не
  влезло» превращалось в «так что-то»;
- пробел после двоеточия — `host:port` и `arXiv:2409.14509` не опечатки;
- апостроф — `resolve'ит` лечится словарём, а не изогнутым `’`.

Неразрывные пробелы по умолчанию тоже выключены: в исходнике Markdown U+00A0 невидим. Для
текста, который уходит в HTML или печать, — ключ `--nbsp`; неразрывный пробел в
выводе показан как `⍽`.

Измерено на десяти русских README соседних проектов: ноль строк к правке после
настройки, при том что на файле с прямыми кавычками и дефисом вместо тире
находка есть. Тишина здесь — обычный исход, как и у грепов в `lexicon.md`.

Вывод — подсказка, а не приговор: строку правит человек, а не `typograf`.
Кавычки внутри цитаты из чужого текста, дефис в названии команды — остаются.
